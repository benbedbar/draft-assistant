Project brief: Fantasy football draft strategy simulator + live draft assistant
Paste this whole document into Claude Code as your starting prompt.
Goal
Build a tool that (1) determines the statistically best draft strategy for my specific league/pick position using Monte Carlo simulation validated against real historical seasons, then (2) provides that strategy as a live recommendation engine during my actual draft, via a Streamlit app.
My league settings
* 10 teams
* Half-PPR scoring (0.5 points per reception)
* I pick 3rd overall (snake draft)
* 15-man roster
* Starting lineup: 1 QB, 2 RB, 2 WR, 1 TE, 2 FLEX (RB/WR/TE eligible), 1 K, 1 DEF (10 starters, 5 bench)
* Note to Claude Code: these are confirmed settings. The two FLEX spots (not one) meaningfully increase RB/WR/TE positional value relative to a standard single-FLEX league — make sure the value-over-replacement (VBD) calculation in Part 3 accounts for both FLEX slots when computing replacement level.
Data sources
1. Current-season player projections: FantasyPros consensus rankings/projections (half-PPR format) — this is the primary "how good is this player" signal, used for value calculations and to score simulated rosters.
2. Current-season ADP: Fantasy Football Calculator or similar, half-PPR — average draft position data, used to model realistic opponent drafting behavior.
3. Historical data (multiple past seasons, ideally 5+): nflverse (nfl_data_py or the R package) for:
   * Weekly actual fantasy point outputs per player (half-PPR scoring), used to build empirical uncertainty distributions
   * Historical ADP for those same seasons, used in the backtest to know what was actually available at each pick
   * Historical final season stats, used in the backtest to score how a drafted roster actually would have performed (not projections — real outcomes)
Part 1: Empirical uncertainty model
Don't assume a theoretical distribution (e.g., normal/bell curve) for player scoring variance. Instead:


1. Pull weekly half-PPR fantasy point totals for all relevant players across multiple past seasons from nflverse.
2. Group players into usage-based archetype buckets by position and role (e.g., "RB1 with 15+ touches/game," "WR2 in a pass-heavy offense," "streaming TE," "low-volume flex WR") rather than relying on any single player's short in-season sample.
3. For each bucket, build the actual empirical distribution of weekly outcomes from real historical weeks — this becomes the uncertainty/variance model, used later to bootstrap-sample realistic weekly outcomes rather than inventing a synthetic distribution.
Part 2: Draft strategies to test
Implement each as a distinct "policy" the simulation can follow when it's my turn to pick:


1. Best Player Available (BPA) — always take the highest value-over-replacement player left, regardless of position. This is the control/baseline.
2. Robust RB — prioritize RB in rounds 1-3 regardless of small value gaps elsewhere.
3. Zero RB — avoid RB entirely in rounds 1-4, load up on WR (and possibly elite TE) instead, circle back to RB in the middle rounds.
4. Hero RB — take exactly one elite RB in rounds 1-2, then pivot hard to WR for several rounds before returning to fill RB depth.


Each policy needs to respect my roster construction constraints (e.g., don't recommend a 3rd QB before I have 2 RB/2 WR filled).
Part 3: Value-over-replacement (VBD) engine
For every player, calculate Value = Player's Projected Points − Replacement Level Points at their Position, where replacement level is derived from my league's exact settings (10 teams × starting lineup slots, accounting for the FLEX spot's cross-position eligibility). This is the core ranking metric every policy uses to compare players across positions.
Part 4: Opponent model
The 9 simulated opponents should NOT draft by rigid ADP order (that produces identical, unrealistic simulations every run). Instead, use ADP-weighted random sampling:


1. At each opponent's pick, calculate a weight for every available player based on how close their ADP is to the current overall pick number (closer ADP = much higher weight, not a hard cutoff — allow rare "reaches" and "falls" just like real drafts).
2. Randomly sample one player from that weighted distribution.
3. Remove that player from the pool and move to the next pick.


Start simple: pure ADP-weighted randomness for all opponents, no positional-need modeling for opponents in v1. This can be refined later once the core loop works.
Part 5: Monte Carlo simulation engine
For each of the 4 policies:


1. Run thousands of simulated drafts from my exact pick slot (3rd overall, 10-team snake), with all 9 opponents using the ADP-weighted random model from Part 4.
2. My own picks in each simulated draft follow the policy being tested (with VBD as the underlying ranking within whatever positional rule the policy applies).
3. Score each resulting 15-man roster using a weekly simulation with variance: for each of 17 weeks, sample each starter's outcome from their empirical uncertainty bucket (Part 1), sum my starting lineup's weekly score, and compare against a simulated league-average opponent score to count "weeks won." Do this across the season for each simulated draft.
4. Aggregate across all simulations per policy: average weekly win totals, distribution of outcomes, not just a single season point total.
Part 6: Backtest validation
For each of the last 5+ real NFL seasons:


1. Pull that season's real historical ADP and simulate each policy drafting from my pick slot, using the real ADP-weighted opponent model (same mechanism as Part 4, but grounded in that season's actual ADP data).
2. Score the resulting roster using that season's REAL final stats (not projections, not simulated variance) — actual games that were actually played.
3. Compare: does the policy that won in Monte Carlo simulation (Part 5) also perform best across these real historical seasons? Flag any strategy where simulation and backtest results diverge significantly — that's a signal the simulation's assumptions need review, not that football is unpredictable.


Output a comparison table: policy name, average simulated weekly win rate, average backtested weekly win rate across all historical seasons tested, and the gap between them.
Part 7: Live Streamlit app
Build this LAST, after Parts 1-6 produce a clear winning strategy. The app should:


1. Load the precomputed winning strategy's round-by-round policy guidance and the current season's VBD-ranked player table (with tiers) at startup — this is fast lookups, not re-running any simulation live.
2. Maintain session state tracking: which players are drafted (mine and opponents'), my current roster composition, and current round/pick number.
3. Provide a simple UI to mark a player as drafted (search/select, whether it was my pick or an opponent's).
4. On every state update, recompute: filter the VBD table to remaining players, cross-reference my roster gaps against the winning policy's targets for this round, and surface tier breaks (positions where the talent pool for the next tier is about to run out).
5. Display a clear, ranked shortlist of recommended picks for my turn, fast enough to use live under draft-clock time pressure.
Suggested build order
1. Data ingestion scripts (FantasyPros projections, current ADP, nflverse historical data)
2. Empirical uncertainty bucket builder (Part 1)
3. VBD engine (Part 3)
4. Opponent model (Part 4) — test standalone, confirm it produces realistic-looking mock drafts before moving on
5. Monte Carlo simulation engine with all 4 policies (Part 2, Part 5)
6. Backtest validation (Part 6)
7. Compare results, resolve any simulation-vs-backtest divergence
8. Streamlit live draft app (Part 7), built around whichever strategy comes out on top
